## Terminal Core benchmarks

Produced by `sprite-term-bench`, which measures only through the public
`TerminalSession` interface. Thirty samples, release build:

```
cargo run --release -p sprite-term --bin sprite-term-bench --locked --offline \
  -- --samples 30 --output target/checkpoint-1-arch.json
```

| Metric | Median (ms) | p95 (ms) | Budget (ms) |
|---|---:|---:|---:|
| `spawn_to_ready` | 0.630 | 0.772 | 0.850 |
| `input_to_snapshot_idle` | 0.114 | 0.129 | 0.142 |
| `input_to_snapshot_under_load` | 9.949 | 13.001 | 14.302 |
| `output_10mib_to_final_snapshot` | 1179.415 | 1403.534 | 1543.887 |
| `capture_100x100_grid` | 0.033 | 0.126 | 0.139 |

Every budget is 110% of that run's p95. The machine-readable report is committed alongside this file as
`checkpoint-1-arch.json`; it is regenerated by the command above, not edited by
hand.

Notes on what these measure:

- `input_to_snapshot_under_load` includes the child's own reaction, because the
  workload has the child stop its producer and echo a marker. Without that, the
  marker scrolls off before any snapshot can show it. The number is therefore an
  upper bound on Sprite's contribution, not a pure input-latency figure.
- `output_10mib_to_final_snapshot` uses 79-character lines. Ten mebibytes with
  no newline at all is a single wrapped line that forces continuous reflow; that
  measures a pathological case rather than ordinary heavy output, so it is
  deliberately not the default workload.
- Scrollback-history capture is not measured. Checkpoint 2 adds that capability.

Graphics retention is zero because Checkpoint 1 allocates no images;
`libghostty-vt` is built with `kitty-graphics` disabled. Checkpoint 4 re-enables
that feature and replaces this metric.

Idle CPU is low but not zero, and no cursor is drawn yet, so the residual is
GPUI/compositor bookkeeping rather than terminal redraw. Zero RSS growth and a
stable thread count over sixty idle seconds is the result that matters here.

RSS of ~167 MiB is large for a terminal and is dominated by GPUI and its Vulkan
stack, not by terminal state. Worth watching, not yet acted on.

### Debug builds are not representative

The 10 MiB workload does not complete within 30 seconds in a debug build, but
takes ~1.2 s in release — more than a 25x gap. Snapshot capture allocates a
`String` per cell, which unoptimized builds punish severely. Two consequences:

- Committed budgets are only ever taken from a release build.
- The benchmark's schema test runs a reduced volume (`--output-bytes`) so
  `cargo test` stays fast against the debug binary. That test validates the
  report's shape, never its numbers.

Per-cell `String` allocation is the obvious first target if these budgets ever
need to improve; Checkpoint 2 touches this code anyway.

## Regression policy

A change that pushes any metric above its budget column is a regression and
blocks merge until explained or fixed. Budgets are re-frozen only by rerunning
the full 30-sample release benchmark on a recorded machine and updating this
file together with the JSON.

## Outstanding gates

These are required by the TSP and have **not** been satisfied. They are listed
here so no reader mistakes this file for a completed acceptance record.

1. **Real macOS baselines.** Never run; no macOS machine is available to this
   workspace. Needs the same 30-sample benchmark, `/usr/bin/time -l` on the app,
   and Activity Monitor idle inspection.

2. **Ghostty comparison at the identical pinned commit.** Not run, for two
   specific reasons:
   - The machine has Ghostty 1.3.1 packaged, which is 1,443 commits *behind* the
     pinned `ab0b9da9`. Comparing against it would not satisfy the requirement
     and would be misleading, so it was not measured.
   - Sprite has no command-line interface yet — the `sprite` binary ignores its
     arguments and always launches a login shell — so an application-level
     like-for-like workload cannot be driven through it. A CLI arrives in
     Checkpoint 5, or this comparison needs a purpose-built harness.

   When it is run: record the commands and results, do not claim Sprite is
   faster, and explain any Sprite p95 above 110% of Ghostty's before accepting
   the budget.

3. **Resize cadence over 10 seconds.** Not measured on either platform. The
   scripted window-manager resize did not take effect, so only the initial
   computed grid was verified.
