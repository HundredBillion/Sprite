# Bound event delivery and recover UI admission

A worker blocked on lossless event publication cannot consume commands. A GPUI settings callback that then synchronously submits Colors and Cursor can exhaust the remaining worker slot while the callback itself prevents the installed event receiver from running. Round9 confirmed this callback cycle; the reserved seventeenth inbox slot only protects one admission.

Use additive `CommandSender::try_send` and `TerminalSession::try_send` for UI input, layout, live settings and observation capture. Saturation is an explicit SessionError and the pane paints its status. Blocking send remains compatible for off-thread callers. Both methods validate variable input: raw input/committed text/combined key data stay within 16KiB; paste retains the existing clipboard limit. Observation uses nonblocking admission while holding its registry mutex and removes the refused request's waiter. Refused hyperlink requests release their pending identities so later pointer/snapshot activity can try again.

A pane keeps one latest desired Settings value and one latest valid Resize. Before the first snapshot, UI fallback colors follow every latest desired settings request independently of worker admission. Colors and Cursor independently remember the last successfully admitted setting; a color success followed by a cursor refusal cannot hide a subsequent revert. Geometry advances its admission cache only after Resize is accepted. One per-view task receives a capacity-one coalesced wake, retries pending values every 50 ms while pressure remains, and sleeps without a timer when no recovery is pending. It also notifies UI of input refusal without requiring a new snapshot. Disconnected/shutting-down admission and ended sessions discard pending work and retire this task. Commands already admitted retain their inbox order; input commands refused under saturation are not replayed automatically.

Replace the bounded channel with one mailbox holding32 ordinary events, at most one accepted parser/command batch's overflow, and at most two final error/child outcomes. Publication transfers a whole16KiB parser chunk's notices and accepted clipboard callbacks before waiting for room. This preserves the remainder of the accepted batch on cancellation; it does not retain future unparsed PTY output. A single capacity-one wake supports both existing EventStream receiver methods. Receiver drop releases retained payloads and wakes the producer. Requested shutdown cancels publication independently of inbox room. Final outcomes seal without awaiting consumption and follow ordinary events and retained overflow. A completion guard publishes an error on unexpected worker termination.

The child waiter starts natural draining before enqueueing its child status, independently of a full inbox or blocked publication. Two seconds stops new reads; accepted output has the existing overall six-second tail budget from child completion. Intermediate snapshots remain skipped during natural drain. If an accepted event batch still waits under pressure, further parsing stops while that batch and final outcomes remain readable. ADR0024's read/tail policy and ADR0025's SID ownership, observed-request decision, and `Option<SessionProcesses>` handoff through `ShutdownHandle::wait` remain intact; natural completion cannot release the late explicit owner's cleanup scope.

Larger channels or another reserved slot only postpone the multi-command cycle. Dropping accepted ordered events hides lifecycle/protocol behavior. An unbounded forwarder or a task per refusal removes useful memory/concurrency bounds. Blocking GPUI until pressure clears retains the demonstrated cycle. The mailbox plus bounded latest-value recovery makes each boundary explicit without those alternatives.

This decision does not establish production deadlock frequency or native macOS behavior; native process adapters retain their separate coverage.
