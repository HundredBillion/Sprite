# Correlate answers by ticket and claim a relayed request before applying it

Observation used to pair a Pane's history answers with waiting requests by arrival order, and every `TerminalEvent::Error` failed the oldest waiter. An unrelated selection or input error therefore answered the wrong request and shifted every later answer by one. History capture now carries a ticket: `CaptureHistory { ticket }` is answered by `History { ticket }` or `HistoryFailed { ticket }`, waiters are keyed by ticket, an answer for an unknown or expired ticket is dropped, and a general `Error` reaches the status line only. Arrival order is no longer part of the contract, so no future event can be misdelivered by being emitted in between. Hyperlink resolution already used a request id and is the precedent.

A relayed request (configuration reload or print, from an endpoint thread to the Sprite Window) used to time out after two seconds with "nothing was changed" while still queued, and the window applied it later. Each relayed request now carries shared `Waiting | Claimed | Abandoned` state. The window applies only after moving `Waiting → Claimed`; a timing-out endpoint moves `Waiting → Abandoned` and only then may say nothing changed. If the window has already claimed it, the endpoint waits up to ten more seconds and otherwise reports that the window accepted the request and is still applying it. Rejected: keeping arrival-order pairing while narrowing which errors resolve waiters (it fixes the symptom and keeps the class), and an unbounded post-claim wait (a wedged UI thread would pin an endpoint thread and connection slot).
