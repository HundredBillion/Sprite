# Bound Surface raster memory across all Surfaces

ADR 0022 bounded decoded pixels per Surface cache (64 MiB) and left memory across Surfaces outside the decision. A Sprite Window hosts up to 64 Surface connections, so the retained-pixel ceiling was about 4 GiB per window, and more with several windows. No memory pressure has been observed; this closes the gap before it is reached.

Every Surface cache now also charges its decoded pixels to one process-wide budget, `MAX_PROCESS_IMAGE_BYTES` = 256 MiB. A decode may use what is left of its own cache's budget or of the process's, whichever is less, and a finished picture is installed only if it still fits both. The per-raster limits (4096 px per side, 16 MiB per bitmap), the filter-primitive cap, the 64 MiB per-cache budget and asynchronous decoding are unchanged. A picture refused for either budget is the same `OverBudget` refusal and draws as an absent image.

256 MiB is four full Surface caches, or sixteen of the largest single rasters, and a sixteenth of the old ceiling. Ordinary icon workloads stay far below it: a 32 px icon is 4 KiB, so 64 Surfaces of 500 distinct icons each retain 125 MiB. A test decodes eight distinct 64 px icons on each of 64 Surfaces and every one is drawn.

The ledger is the cache's own retained-byte count. Every change to it goes through one method that charges or refunds the difference to the process total, so the process total is always the sum over live caches. The paths are: installing a finished decode (charge); keeping only the images a new description or tab snapshot draws (refund what was dropped); resetting a list for a new icon raster width (refund all); and dropping a cache with its Surface or view (refund all). A decode that finishes after its cache was dropped is never installed, so it is never charged. Caches are shared through `Rc` and live on the UI thread, so the ledger is a thread-local cell, not an atomic; tests get one per test thread, which keeps parallel tests from sharing a budget.

Refusals for lack of budget are retried under the existing rules, now measured against both budgets. A decode that was refused for lack of the bytes it started with goes back to the front of its queue if, by the time it finishes, more is free, including room another Surface freed. An element Surface or tab strip forgets such a refusal when its next description or snapshot arrives and tries again. A list keeps every outcome until its icon raster width changes, as before.

Consequence: a refusal that has already settled is not retried when a different Surface frees room; it waits for its own Surface's next description. Waking other Surfaces' views on release would need the ledger to hold callbacks into GPUI views; that was not built, because the budget is a safety bound that ordinary workloads do not reach. Rejected: a fixed per-Surface share (256 MiB / 64 = 4 MiB) would refuse a single large image on one Surface while the rest of the budget sat idle. Rejected: least-recently-used eviction of ready pictures across Surfaces would make pictures on screen disappear and need a cross-Surface redraw path; first come, first served admission keeps what is drawn stable. Like ADR 0022, this bounds retained bitmap data only, not usvg parse allocations, CPU time or native texture copies.
