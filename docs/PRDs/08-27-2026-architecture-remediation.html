Defects found while reading

All five verified against source. Revised framing: the original review said each defect lives in a module no test can reach. That holds for two of them, not four. Defects 1 and 4 are plain coverage gaps in code that already has tests beside it — sprite-term/tests/colors.rs and the config_request tests respectively. Only defects 2 and 3 are genuinely GPUI-locked. Defect 5 was found by running C7, not by reading. The case for the candidates rests on two defects, not three.

colours never repaint ◆

sprite-term/src/worker.rs:658, 670

SetColors and SetCursor are the only mutating arms that never set dirty. They send CaptureRequested, which wakes the loop to re-evaluate a gate that is still false — if dirty && snapshots.is_empty() at :755. No Render Snapshot is produced.

Line 657, immediately above, shows the correct idiom: Capture => dirty = true. Masked in-app because GPUI redraws the last snapshot, so a live colour reload appears only after the next keystroke.

close guard has a hole ◆

sprite-app/src/main.rs:100 vs workspace.rs:298

may_close has exactly two callers — close_focused_pane and close_active_tab. The window-manager close button calls begin_shutdown and returns true unconditionally.

PRD story 11 wants "a deliberate close confirmation … so that I do not accidentally terminate work". Its acceptance criteria (PRD:417–426) enumerate only pane close and tab close, so the title-bar X is a gap against the story's intent, not a stated criterion. Ctrl+Shift+W (ClosePane) and Ctrl+Shift+Q (CloseTab) are both guarded.

a failed pane is reported as a timeout ◆

observation/panes.rs:150 · terminal_view.rs:340 · broker.rs:353

deliver_failure is never called. It is the error counterpart to deliver, so nothing ever hands an observation waiter an Err. A pane that genuinely fails is not reported — the requester waits out the full 500 ms DEADLINE and is then told FailureKind::Timeout, which is the wrong reason.

FailureKind::Errored is therefore unreachable in production. It exists, and broker.rs:779 asserts it against a fake. terminal_view.rs:340 handles TerminalEvent::Error by setting view.status and never touches link.panes. Found by narrowing lib.rs and letting dead_code report it — i.e. by C7.

protocol version divergence ◆

observation/broker.rs:194 vs workspace.rs:574

broker::parse refuses a newer protocol token (spoken != PROTOCOL). config_request consumes any sprite-observation/* token without checking.

sprite-observation/99 config reload reloads. sprite-observation/99 panes snapshot is refused.

Implementation plan

Settled in a grilling session, 31 Aug 2026. Ten decisions, each recorded with the reasoning that produced it. Where a decision contradicts the card below, this section wins.

Branch one — defects, shipped ahead of all structural work

Roughly 40 lines of change. Three of five defects are user-visible. Kept separate so that every diff in branch two carries no behaviour change, which is what makes a refactor reviewable.

Defect 1 — colours never repaint

dirty = true; in both arms, keep the CaptureRequested self-send, and comment :438 to say what it is for. The one-slot snapshot channel (SNAPSHOT_CAPACITY = 1) means the flag alone is not sufficient: if the slot is occupied the gate skips and the loop blocks on recv(). The self-send buys a second pass at the gate. An empty match arm doing load-bearing work is what let this survive review, so it gets a comment rather than a deletion.

Verified by: integration test in sprite-term/tests/colors.rs — send SetColors to a running session, assert the new colours are present in the next snapshot. The harness watchdog (support/mod.rs:95) fails loudly rather than hanging.

Defect 2 — close guard has a hole

Add CloseScope::Window, sourcing its running set from Tabs::all_panes() so it spans every tab. on_window_should_close calls may_close and returns false to refuse — GPUI 0.2.2 honours this (wayland/window.rs:542). Reuse the existing banner rather than introducing a modal; add CloseScope::again() so it reads "click close again" for the X and keeps "press the same keys again" for the bindings.

Deliberate: any keystroke cancels a pending window close, because a Window scope can never match ClosePane|CloseTab at :962. That is correct — typing means the person moved on — and is recorded here so it is inherited on purpose. Ctrl+Shift+Q stays Tab scope: with one tab the two scopes see identical panes, and making a binding's meaning depend on tab count is worse than the cosmetic inconsistency.

Verified by: manual check, written into the PR. Run Sprite; start sleep 30 in a pane; click the title-bar X; confirm the banner appears and the window survives; click X again; confirm it closes. Repeat with an idle shell and confirm one click closes it. may_close needs a live Context<Workspace>, so no automated test is possible before C1.

Defect 4 — protocol version divergence

Hoist the check into respond: one protocol_check(body) -> Result<&str, Refusal> validating and stripping the token ahead of the dispatch, so both verbs pass through it. This fixes the divergence by construction rather than by keeping two checks in step, and is a down-payment on C4. broker::parse keeps its own token handling untouched — it is public API used by the bench, and after the hoist it simply never sees a token from the endpoint path.

In scope: respond(panes: &WindowPanes, …) becomes respond(panes: &dyn PaneSource, …). One word. broker::collect is already written against the trait; respond is the only part of the subsystem tied to the concrete type, which is why no test can call it. The call site at :502 coerces unchanged.

Verified by: unit test calling respond through a six-line PaneSource fake, asserting sprite-observation/99 config reload and … panes snapshot are both refused. Testing config_request alone cannot pin this — the defect is that the two paths disagree. The refusal happens before ask_window, so the 2-second RELOAD_TIMEOUT is never reached.

Not in branch one

Defect 3 (Self::failed forks a shell) rides with C1 — its clean fix, session: Option<TerminalSession>, touches every self.session use in the file C1 is already rewriting. Note: C1's win list claims the extraction earns this fix. It does not — the pump never touches the session field. Batching them is a review convenience, not a causal relationship.

Defect 5 (deliver_failure) rides with C1 — the fix lives in the TerminalEvent::Error arm, which is one of the thirteen arms C1 rewrites, and C1 is what makes it testable. There is a judgment call inside it: that arm fires for any session error, so calling deliver_failure there fails any in-flight request whenever the pane reports anything wrong. That is the intended behaviour — a pane in a bad state should not leave a requester waiting out the deadline.

C1 — the pump's interface

Reading all thirteen arms changes the design. Every arm only writes view state; none reads it. So the decision half is a pure, stateless function — the fields stay on the view and the pump owns nothing. That is a better outcome than this document's "pump absorbs 3 of 23 fields": there is no new state at all, and the view's field count is unchanged.

// terminal_events.rs — beside terminal_view.rs, not inside it
enum Effect {
    Status(SharedString),
    HoldPaste(String),
    OpenUrl(String),
    Clipboard(String),
    DeliverHistory(HistorySnapshot),
    FailRequest(String),      // defect 5
}
struct Decision { effects: Vec<Effect>, stop: bool }
fn decide(event: Result<TerminalEvent, StreamError>) -> Decision

notify is implicit: apply calls cx.notify() once if any effect was applied. Fewer variants, and it removes the current bug-shape where an arm notifies for nothing. Max effects for one event is two (UnsafePaste, Error). The async loop becomes three lines and holds no logic. decide lives in a new terminal_events.rs — terminal_view.rs is the 1,581-line file this card exists to shrink, so its tests should not land there either.

Rejected: a Pump struct owning the three fields (invents state the code does not need, and still has to reach the view to apply anything); a PumpHost trait (one real implementor — the shallow-seam pattern this review argues against elsewhere).

C3 splits

C3a — bundle the parameters. One value holding the five scratch objects, passed as one argument. Both too_many_arguments suppressions go, publish's 31 lines collapse, capture drops from nine parameters to three, and the threading through four sites disappears. Changes no drop behaviour — keep the explicit drop() list exactly as it is, now against the struct's fields. Covered by the existing integration suite.

C3b — encode the ordering in Drop. Gated, not scheduled. This card's central promise is that drop order becomes a Drop impl rather than the worker's discipline. You cannot encode an invariant the codebase states two different ways and the compiler cannot check either. worker.rs:792 says "Every libghostty value goes first", but the list at :795–799 omits placements, one of the four objects render_objects() returns. All four are declared 'static, so these are not Rust borrows — the ordering concerns libghostty's internal state, which the compiler will never check. A Drop impl written now would freeze a guess, and because Drop fires implicitly, a future reader would have less signal than the explicit list gives.

Acceptance criteria

Four cards are justified entirely by a testability claim. For those, landing the promised test is the acceptance criterion — a refactor that ships without it has spent the effort and preserved the original condition, which is that nobody can verify this code.

  • C1 — decide unit-tested across all thirteen arms with no GPUI in the test binary, including the two that emit two effects, plus the defect-5 regression: an Error event produces FailRequest.
  • C4 — respond tested directly through &dyn PaneSource: read path, config path, protocol refusal on both. Branch one's defect-4 test becomes the first of these, which doubles as a check that C4 changed no behaviour.
  • C5 — round-trip test, Query → wire text → Query across every scope and flag combination. This is what actually retires the two-Scope-enums problem: it fails if the two directions ever disagree.
  • C6 — promise restated. The original claim, "GridPaint::draw becomes testable", overpromises: draw paints into a GPUI Window, and moving colour vocabulary into the painter does not by itself make painting testable. What C6 genuinely earns is cell_colors — the 50-line colour resolution block — testable as a pure function. That is the criterion.

For C7, C8, C9 and C11 the criterion is the existing suite green — and for C7 specifically, cargo check clean with narrowed exports and no new #[allow(dead_code)] added to silence anything.

Dropped, dissolved, and open

C2 — dropped. Observed, not actioned. Its headline defect was withdrawn: there is no permanent focus disagreement, and no caller sequence reaching the drop at workspace.rs:480 could be constructed. What remains is a real complexity argument — focus in six places across five modules, five hops to answer one question, six of PaneRegistry's fourteen methods pure delegation — but it would be the only card justified purely by navigability, it has the widest blast radius here, and no test can fail if it is done wrong. Revisit if a focus bug ever appears; that bug would then tell you where the ownership boundary belongs.

C10 — dissolved. Not a card. terminal_view.rs:288 is one of the thirteen arms C1 rewrites — under decide it is never written rather than deleted. workspace.rs:558 waits for C4, because removing those arms properly means narrowing collect's error type, not adding a catch-all that would answer "denied" to a malformed request. Eight candidates remain, not eleven.

Open question, for whoever picks up C3b: must placements drop before terminal? If yes, the current code has a latent bug and that is a defect, not a refactor. If no, the comment at :792 is wrong and should be narrowed to name the three values that do matter. This is a libghostty question rather than a Sprite one, and it does not block the eight cards ahead of it.

Unverified claim, inherited: C10's "five doc comments attached to the function below the one they describe" was never re-read against source. Confirm before acting on it.

The 165 kept lines are real: clamp-and-report for font.size and scrollback.bytes, per-entry survival in colors.palette against whole-list rejection for shell.args, empty-string handling, and fourteen distinct complaint strings each asserted on by name.

Checked and rejected

Candidates that looked obvious and failed the deletion test. Recorded so the next review does not re-propose them.

serde derive for schema.rs — no

The 1,134 lines are 464 production, 669 tests, and it encodes only — no decoding, no validation. Every wire key is renamed relative to its source; the source is a foreign type, so a wire struct would cost two lines per field where hand-writing costs one. ADR-0006 exists precisely so a field added for the renderer cannot silently appear on the wire, and a test asserts the exact key set. Deep — keep.

serde derive for config.rs — no

It would delete all 92 boilerplate lines and break the rule the file exists for: "absent or invalid configuration produces defaults rather than an error". serde aborts the document on the first type error, so one mistyped graphics.enabled would lose the other fourteen settings. Per-field fallback needs a deserialize_with shim per field — more code than the arm it replaces. Deep — keep.

PaneSource — a real seam

The workspace's only trait, and it has three adapters: WindowPanes, the bench's Panes, the test's FakeWindow. Two adapters make a seam real. Its interface is also deliberately narrow — no method writes — which is the structural half of ADR-0013.

png_decoder.rs — not a reinvention

It is an adapter over the real png crate, installed through set_png_decoder because GPUI's bundled RustPngDecoder has a private field, no constructor, and hands next_frame a zero-length buffer. The workspace manifest documents this at length.

config.rs::to_toml — keep

Not a serializer in disguise: the toml dependency is parse-only so there is no to_string, every unset value is printed as a comment naming its consequence, and round-tripping is a tested contract.

No dead config fields

All 15 settings are read, each traced to a consumer. classify's 35 lines for 7 comparisons are not collapsible either — the live-vs-next-session grouping is the product decision ADR-0002 requires.

Top recommendation

Cut the event pump out of the Pane view

It is the smallest cut with the largest testability gain: 120 lines that depend on none of the other sixteen responsibilities, currently unreachable because cx.spawn needs an Entity<Self>. Three of the four defects above live in modules with exactly this shape — behaviour that only a running GPUI Window can reach, so no test does.

Start here rather than with the deeper focus ownership work: this one needs no decision about who owns what, and it makes the next four candidates testable as you do them. If you want a warm-up first, the 37 dead lines cost nothing and switch the compiler back on as a guard.
